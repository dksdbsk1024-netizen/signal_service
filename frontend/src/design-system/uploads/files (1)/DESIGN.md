# DESIGN.md — 종목 매매신호 서비스

> 종목을 검색하면 여러 지표를 종합해 **매수/매도 방향성**을 알려주되,
> 씽크풀 같은 블랙박스가 아니라 **각 지표의 기여도를 전부 공개**하고
> 사용자가 **가중치까지 직접 조절**할 수 있는 투명한 매매 보조 도구.
> **경제지표(매크로) 맥락**을 함께 보고, 신호 판단부터 **매매 계획(리스크)**까지 한 흐름으로 연결한다.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 목적 | 국내 주식 데이트레이딩용 종목 매매신호 대시보드 |
| 핵심 차별점 | ① 스코어링 로직 완전 공개 ② 사용자별 가중치 커스터마이징 ③ 신호→매매계획 한 흐름 ④ 경제지표 맥락 결합 |
| 대상 | 본인(트레이더) 우선, 추후 서비스 확장 가능성 열어둠 |
| 데이터 | 분봉·실시간(종목) + 경제지표·시세(매크로) |

### 벤치마크 대비 포지셔닝
- **씽크풀 RASSI**: 빅데이터를 점수화해 신호를 주지만 로직이 블랙박스.
- **본 서비스**: "한 줄 신호"를 주되 **왜 그 신호인지**를 지표별 점수로 분해하고, 가중치를 조절하며, **경제지표 국면**까지 함께 본다 → "신호기"가 아니라 "판단+실행 보조 도구".

---

## 2. 설계 원칙

1. **데이터 ↔ 로직 분리**: 데이터 소스와 스코어링 로직을 분리한다. 소스를 바꾸거나 백테스팅으로 확장해도 로직은 그대로 재사용.
2. **투명성 우선**: 모든 신호는 지표별 기여 점수로 분해 가능. 블랙박스 금지.
3. **로직은 프레임워크 독립**: 지표 계산·스코어링은 순수 Python 모듈.
4. **종목 ↔ 매크로 분리**: 종목 데이터와 경제지표/시세는 성격이 다르므로 레이어를 분리하되 UI에서 연결.
5. **판단→실행 연속성**: 신호(판단)와 리스크(실행 계획)를 한 화면에서 완결.
6. **점진적 확장**: 코어부터 완성하고 부가 기능을 단계적으로 얹는다.

## 6. 데이터 레이어 (`providers.py`)

```
StockProvider (추상)                      MacroProvider (추상)
├── get_minute_ohlcv(ticker, interval)    [경제지표]
├── get_investor_flow(ticker)             ├── get_economic_indicator(name)  # CPI·PPI·금리 (실제/예상/이전)
├── get_orderbook(ticker)                 ├── get_release_calendar()        # 발표 일정
└── get_trade_strength(ticker)            [시세]
                                          ├── get_index(name)   # 코스피·나스닥 등
                                          ├── get_fx(pair)      # 원/달러
                                          └── get_volatility()  # VIX
구현체:
├── KISProvider       # 종목 (실전)
├── MacroDataProvider # FRED·ECOS(경제지표) + yfinance·FDR(시세) + 경제캘린더(예상치·일정)
└── MockProvider      # 합성 데이터. API 키 없이 개발·UI 테스트용
```

- **신선도(as_of) 라벨 필수**: 경제지표는 발표 주기(월/분기), 시세는 실시간~전일로 시점이 제각각. 각 데이터에 기준 시점 표기.
- **경제지표 3종 값**: 실제치·예상치·이전치를 함께. 예상치·발표일정은 FRED/ECOS에 없어 경제캘린더 별도 소스 필요(구현 난이도 ↑).

## 7. 지표 레이어 (`indicators.py` / `macro.py`)

### 종목 지표 (`indicators.py`)
| 카테고리 | 지표 |
|----------|------|
| 수급 | 외국인·기관 순매수, 프로그램 매매 |
| 추세 | 이평선 배열(5·20·60), 현재가 vs VWAP |
| 모멘텀 | RSI, MACD 히스토그램, 스토캐스틱 |
| 거래량 | 평균 대비 거래량 급증 여부 |
| 변동성 | 볼린저 밴드 위치, ATR |

### 매크로 (`macro.py`)
**경제지표** (메인)
| 지표 | 소스 | 값 형태 |
|------|------|---------|
| 미국 CPI / 근원 CPI | FRED (CPIAUCSL / CPILFESL) | 실제·예상·이전, 전년/전월 |
| 미국 PPI / 근원 PPI | FRED (PPIACO 등) | 〃 |
| 미국 기준금리 | FRED (FEDFUNDS) | 현재 수준·다음 FOMC |
| 한국 CPI / PPI | 한국은행 ECOS | 〃 |
| 한국 기준금리 | ECOS | 현재·다음 금통위 |
| 발표 일정 | 경제캘린더 | 다음 발표일 D-day |

**시세** (보조)
| 지표 | 소스 |
|------|------|
| 코스피·코스닥, 시장 수급 | KIS |
| S&P·나스닥·다우, VIX | yfinance |
| 원/달러 환율 | yfinance / ECOS |
| 국채 금리(미10Y 등) | FRED |

> 경제지표는 **실제치 vs 예상치(서프라이즈)**가 시장을 움직이므로, 이 갭을 핵심으로 표시.

## 8. 스코어링 엔진 (`scoring.py`) — 핵심

### 산출 절차
1. **정규화**: 각 지표를 `-100 ~ +100` (+는 매수 우호).
2. **가중합**: `최종스코어 = Σ (지표점수 × 가중치)`. 가중치는 `config.py` 기본값 + 사용자 조절값.
3. **라벨링**:

| 최종 스코어 | 라벨 |
|-------------|------|
| +60 ~ +100 | 적극 매수 |
| +20 ~ +60 | 매수 |
| -20 ~ +20 | 중립 |
| -60 ~ -20 | 매도 |
| -100 ~ -60 | 적극 매도 |

4. **기여도 분해**: 각 지표의 기여 점수를 리스트로 반환 → UI 막대로 시각화.

### 리스크 계산 (탭1 매매계획 섹션에서 사용)
- ATR 기반 손절가/목표가 (1×/1.5×/2× ATR)
- 손익비(R:R)
- 포지션 사이징: 계좌 크기 · 리스크(%) → 매수 수량

### 매크로 결합 (확장 여지)
- 1차: 경제지표·시세는 **표시만**(탭4). 종목 스코어와 독립.
- 2차(옵션): 물가 서프라이즈·금리 국면을 종목 스코어 가중에 반영. 설정에서 on/off.

## 9. UI 정보 구조 (탭 구성)

정보를 목적별로 묶어 탭을 분리. **설정은 탭이 아니라 우측 상단 톱니바퀴 아이콘 → 모달/패널.**

> ⚠️ 아래는 **정보 구조**만 정의. 각 화면의 **구체 비주얼은 Claude Design에서 확정** — 본 문서에서는 비워둠.

**탭 바 순서**: `① 종합 신호 · ② 기술적 분석 · ③ 수급 · ④ 매크로 · ⑤ 스크리너`  +  `⚙ 설정(아이콘)`

### 탭 1 — 종합 신호 + 매매 계획 _(판단 → 실행)_
"사? 팔아?"에 즉답하고, 그대로 매매 계획까지 세운다. **두 섹션으로 명확히 구분**(구분선/앵커).

**[섹션 A · 종합 신호]**
- 시장 상태 배너 (상단, 얇게) — 경제지표/시세 요약. 클릭 시 탭 4로
- 종목 기본정보 (현재가·등락률·거래량·시가총액)
- 종합 방향성 게이지 (최종 매수/매도 라벨) — 히어로
- 지표별 기여도 요약 (막대)
- 축소판 캔들 + VWAP 차트
- 신호 히스토리 — 당일 신호 변화 타임라인

**[섹션 B · 매매 계획]**
- 진입가 입력 → ATR 기반 손절가/목표가 자동 제안
- 손익비(R:R) 시각화
- 포지션 사이징 (계좌 크기·리스크 % → 매수 수량)

> ⚠️ 세로로 길어지므로 섹션 A(결론)를 상단에 고정 노출, 섹션 B는 구분선 아래. 섹션 A의 "3초 결론" 성격 유지.

### 탭 2 — 기술적 분석 _(차트 딥다이브)_
- 메인 캔들 차트 (이평선·VWAP·볼린저 오버레이)
- 거래량 바
- 서브차트: RSI, MACD, 스토캐스틱
- 지표별 현재값·신호 테이블
- 타임프레임 전환 (1분 / 5분 / 일봉)

### 탭 3 — 수급 _(돈의 흐름)_ ⭐ 국내 단타 핵심
- 외국인·기관 순매수 추이
- 프로그램 매매 동향
- 체결강도 (매수/매도 체결 비율)
- 호가창(Level 2)
- 거래원 정보 (창구별 매수/매도)

### 탭 4 — 매크로 _(시장의 숲)_ ⭐ 두 섹션
종목과 무관하게 시장 환경을 본다. **경제지표(메인) + 시세(보조)** 두 섹션.

**[섹션 A · 경제지표]** (메인)
- 지표 카드 — CPI·PPI·기준금리 등. 각 카드에 `실제치 / 예상치 / 이전치 + 서프라이즈`
- 발표 캘린더 — "다음 CPI까지 D-8" 카운트다운 + 이번 주 주요 발표(금통위·FOMC 등)
- 추세 미니 차트 — 각 지표 최근 6~12개월
- 한국 / 미국 구분

**[섹션 B · 시세]** (보조)
- 국내 지수 (코스피·코스닥) / 해외 (S&P·나스닥)
- 원/달러 환율, 국채 금리
- VIX 등 변동성

### 탭 5 — 관심종목 / 스크리너 _(종목 발굴)_
- 워치리스트별 실시간 신호 현황
- 조건 스크리너 (예: VWAP 상향돌파 + 거래량 급증 + RSI 다이버전스)
> 다종목 조회로 API 호출 급증 → 데이터 연동은 실전 계좌·최적화 후. UI 선구현.

### ⚙ 설정 _(탭 아님 — 아이콘/패널)_ ⭐ 투명성의 핵심
- 스코어링 가중치 조절 + 프리셋(수급/모멘텀/균형)
- 매크로 결합 on/off
- 알림 임계값, 지표 파라미터(RSI 기간 등)

## 10. 개발 우선순위 (로드맵)

| 단계 | 범위 | 비고 |
|------|------|------|
| **코어 (필수)** | 탭 1(신호+매매계획)·2·3 | 서비스의 최소 완결 형태 |
| **맥락 (권장)** | 탭 4 (경제지표+시세) | FRED/ECOS/경제캘린더 연동 |
| **차별화 (강력 추천)** | 설정 패널 (가중치·프리셋) | 씽크풀과 구별되는 정체성 |
| **확장 (v2)** | 탭 5 (스크리너) | 다종목 = API 호출 급증 → 실전 계좌 후 |

**작업 순서 제안**
1. `core/` 로직 완성 (indicators + scoring + 리스크 계산) → MockProvider로 검증
2. `KISProvider` 실연동 → `MacroDataProvider`(경제지표 우선, 시세 후순위)
3. FastAPI 엔드포인트 구성
4. Claude Design UI 확정 → 본 문서 UI 섹션 비주얼 채우기
5. React 프론트 구현 (Claude Code)

## 11. 제약사항 / 유의점

- **API 키 필수**: KIS는 계좌 + 앱키 발급 필요. 이용기간 1년, 초당 호출 제한.
- **경제지표 예상치·일정**: FRED/ECOS엔 실제/과거치만. 예상치·발표일정은 경제캘린더 별도 소스 필요(구현 난이도 ↑).
- **매크로 신선도 편차**: 경제지표는 발표 주기, 시세는 실시간~전일 → as_of 라벨 필수.
- **모의투자 호출 제한**: 연속 호출 많은 스크리너는 실전 계좌 권장.
- **컨테이너 테스트 불가**: 실 API는 개인 인증·로컬 실행 → 개발은 로컬(Claude Code).
- **신호는 참고용**: 지표는 후행 특성. 진입·청산은 직접 판단. 손절 규율·손익비가 승률보다 중요.

2. 결과의 디자인 토큰(색·타이포·컴포넌트)을 9번 각 탭 하위 및 BRIEF에 반영(사용자가 직접).
3. 완성 문서를 Claude Code 작업 폴더에 두고 프론트 구현.
