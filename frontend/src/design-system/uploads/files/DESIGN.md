# DESIGN.md — 종목 매매신호 서비스

> 종목을 검색하면 여러 지표를 종합해 **매수/매도 방향성**을 알려주되,
> 씽크풀 같은 블랙박스가 아니라 **각 지표의 기여도를 전부 공개**하고
> 사용자가 **가중치까지 직접 조절**할 수 있는 투명한 매매 보조 도구.
> 여기에 **시장 전체(매크로) 맥락**을 겹쳐, 개별 종목 신호를 시장 국면 위에서 판단한다.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 목적 | 국내 주식 데이트레이딩용 종목 매매신호 대시보드 |
| 핵심 차별점 | ① 스코어링 로직 완전 공개(투명성) ② 사용자별 가중치 커스터마이징 ③ 매매 계획(리스크) 도구 내장 ④ 매크로 맥락 결합 |
| 대상 | 본인(트레이더) 우선, 추후 서비스 확장 가능성 열어둠 |
| 데이터 | 분봉·실시간(종목) + 지수·환율·금리·변동성(시장) |

### 벤치마크 대비 포지셔닝
- **씽크풀 RASSI**: 빅데이터를 점수화해 매수/매도 신호를 주지만 로직이 블랙박스.
- **본 서비스**: 동일하게 "한 줄 신호"를 주되, **왜 그 신호인지**를 지표별 점수로 분해해 보여주고, 사용자가 전략에 맞게 가중치를 조절하며, **시장 국면(리스크온/오프)**까지 함께 본다 → "신호기"가 아니라 "판단 보조 도구".

---

## 2. 설계 원칙

1. **데이터 ↔ 로직 분리**: 데이터 소스(증권사/매크로 API)와 스코어링 로직을 완전히 분리한다. 소스를 바꾸거나 백테스팅으로 확장해도 로직은 그대로 재사용.
2. **투명성 우선**: 모든 신호는 지표별 기여 점수로 분해 가능해야 한다. 블랙박스 금지.
3. **로직은 프레임워크 독립**: 지표 계산·스코어링은 순수 Python 모듈로, 웹 프레임워크에 의존하지 않는다.
4. **종목 ↔ 시장 분리**: 개별 종목 신호와 시장 전체 상태는 서로 다른 데이터 성격이므로 레이어를 분리하되, UI에서는 연결해 보여준다.
5. **점진적 확장**: 코어(신호·기술·수급)부터 완성하고 부가 기능을 단계적으로 얹는다.

---

## 3. 기술 스택

| 레이어 | 기술 | 비고 |
|--------|------|------|
| 로직 | Python 3.11+ (pandas, numpy) | 프레임워크 독립 순수 모듈 |
| 백엔드 | FastAPI | 비동기, 빠른 응답. 실시간 분봉/웹소켓에 유리 |
| 프론트 | React | UI 자유도 확보. Claude Design → Claude Code 핸드오프 |
| 데이터(종목) | 한국투자증권 KIS Developers API | 조회 무료. 분봉·수급·호가. `python-kis` 활용 가능 |
| 데이터(매크로) | FinanceDataReader / yfinance / FRED | 해외 증시·환율·금리·VIX 등 |
| 배포(선택) | 프론트=Vercel / 백엔드=Render | 무료 티어로 시작 가능 |

> **속도**: 실행 속도는 FastAPI+React가 Streamlit보다 유리(Streamlit은 인터랙션마다 전체 재실행).
> **비용**: 로컬 개발·실행 및 조회 API는 무료. 배포도 무료 티어로 시작, 트래픽 증가 시에만 유료 전환.

## 4. 시스템 아키텍처

```
[KIS API: 종목]   [FDR/yfinance/FRED: 매크로]        [React 프론트엔드]
       │                    │                              │
       ▼                    ▼                              │ (HTTP/WebSocket)
┌─────────────────────────────────┐                       ▼
│           providers             │  분봉·수급·호가 /   ┌──────────────┐
│        (데이터 레이어)           │  지수·환율·VIX 등  │   FastAPI    │
│  StockProvider / MacroProvider  │ ─────────────────▶ │  (API 레이어) │
└─────────────────────────────────┘                    └──────────────┘
       │                                                       ▲
       ▼                                                       │
┌──────────────┐        ┌──────────────┐                       │
│  indicators  │ ─────▶ │   scoring    │ ──────────────────────┘
│  (지표 계산)  │        │ (스코어 엔진) │   종목 방향성 + 기여도 / 시장 국면
└──────────────┘        └──────────────┘
```

**흐름 요약**: providers(종목·매크로)가 데이터를 가져오면 → indicators가 지표를 계산하고 → scoring이 종목 방향성 스코어(+기여도)와 시장 국면(리스크온/오프)을 산출 → FastAPI가 JSON으로 서빙 → React가 탭별로 시각화.

## 6. 데이터 레이어 (`providers.py`)

소스에 종속되지 않도록 **추상 인터페이스**를 두고 구현체를 갈아끼운다.

```
StockProvider (추상)                      MacroProvider (추상)
├── get_minute_ohlcv(ticker, interval)    ├── get_index(name)          # 코스피·코스닥·S&P·나스닥
├── get_investor_flow(ticker)             ├── get_fx(pair)             # 원/달러 등
├── get_orderbook(ticker)                 ├── get_rate(name)           # 국고채·미국채
└── get_trade_strength(ticker)            ├── get_volatility()         # VIX·공포탐욕지수
                                          └── get_market_flow()        # 외국인·기관 시장 전체 순매수
구현체:
├── KISProvider      # 한국투자증권 실전 (종목)
├── MacroDataProvider# FinanceDataReader/yfinance/FRED (매크로)
└── MockProvider     # 합성 데이터. API 키 없이 개발·UI 테스트용
```

- 개발 초기엔 `MockProvider`로 UI·로직을 완성하고, 이후 실 provider로 교체.
- **데이터 신선도 편차 주의**: 국내 지수·수급은 실시간, 해외 증시는 전일 종가/야간 선물, 환율·금리는 소스별 지연이 다름 → 각 데이터에 기준 시점(as_of) 라벨 필수.
- 모의투자 계좌는 호출 제한이 빡빡하므로 연속 호출 많은 스크리너는 실전 계좌 권장.

## 7. 지표 레이어 (`indicators.py` / `macro.py`)

### 종목 지표 (`indicators.py`)
| 카테고리 | 지표 |
|----------|------|
| 수급 | 외국인·기관 순매수, 프로그램 매매 |
| 추세 | 이평선 배열(5·20·60), 현재가 vs VWAP |
| 모멘텀 | RSI, MACD 히스토그램, 스토캐스틱 |
| 거래량 | 평균 대비 거래량 급증 여부 |
| 변동성 | 볼린저 밴드 위치, ATR |

### 시장 국면 (`macro.py`)
| 카테고리 | 지표 |
|----------|------|
| 국내 지수 | 코스피·코스닥 등락, 상승/하락 종목 비율 |
| 해외 선행 | 간밤 S&P·나스닥, 야간 선물 |
| 환율·금리 | 원/달러, 국고채·미국채 금리 |
| 시장 수급 | 외국인·기관 시장 전체 순매수 |
| 심리·변동성 | VIX, 공포·탐욕 지수 |
| 섹터 | 업종별 강도(히트맵) |

> 시장 국면은 이들을 종합해 **리스크온 / 중립 / 리스크오프**로 판정. (탭1 배너 + 매크로 탭에서 공용)

## 8. 스코어링 엔진 (`scoring.py`) — 핵심

각 지표를 개별 점수로 만들고, 가중합해 최종 방향성을 낸 뒤 **기여도를 반드시 함께 반환**한다.

### 산출 절차
1. **정규화**: 각 지표를 `-100 ~ +100` 점수로 변환 (+는 매수 우호, -는 매도 우호).
2. **가중합**: `최종스코어 = Σ (지표점수 × 가중치)`. 가중치는 `config.py` 기본값 + 사용자 조절값.
3. **라벨링**: 최종 스코어를 구간별로 매핑.

| 최종 스코어 | 라벨 |
|-------------|------|
| +60 ~ +100 | 적극 매수 |
| +20 ~ +60 | 매수 |
| -20 ~ +20 | 중립 |
| -60 ~ -20 | 매도 |
| -100 ~ -60 | 적극 매도 |

4. **기여도 분해**: 각 지표가 최종 스코어에 몇 점 기여했는지 리스트로 반환 → UI에서 막대로 시각화.

### 시장 국면 결합 (확장 여지)
- 1차: 시장 국면은 **표시만** 한다(탭1 배너). 종목 스코어와 독립.
- 2차(옵션): 리스크오프 국면에서 매수 신호를 디스카운트하는 등, 시장 국면을 종목 스코어 가중에 반영. 설정에서 on/off.

### 반환 스키마(예시)
```json
{
  "ticker": "065510",
  "final_score": 42,
  "label": "매수",
  "market_regime": "risk_on",
  "contributions": [
    {"indicator": "수급(외국인·기관)", "score": 70, "weight": 0.30, "contribution": 21.0},
    {"indicator": "VWAP",           "score": 55, "weight": 0.20, "contribution": 11.0},
    {"indicator": "RSI",            "score": 30, "weight": 0.15, "contribution": 4.5},
    {"indicator": "거래량",          "score": 40, "weight": 0.15, "contribution": 6.0}
  ],
  "as_of": "2026-07-03T13:20:00+09:00"
}
```

## 9. UI 정보 구조 (탭 구성)

정보를 목적별로 묶어 탭을 분리한다. 매매 동선(종목 판단) 탭을 앞에, 시장·발굴 탭을 뒤에 배치.
**설정은 탭 바에서 제외** → 우측 상단 톱니바퀴 아이콘 → 모달/패널.

> ⚠️ 아래는 **정보 구조(무엇을 담을지)**만 정의한다.
> 각 화면의 **구체 비주얼(레이아웃·색·타이포·컴포넌트 스타일)은 Claude Design에서 확정** — 본 문서에서는 비워둠.

**탭 바 순서**: `① 종합 신호 · ② 기술적 분석 · ③ 수급 · ④ 리스크/전략 · ⑤ 매크로/시장 · ⑥ 스크리너`  +  `⚙ 설정(아이콘)`

### 탭 1 — 종합 신호 _(한눈에 답)_
"사? 팔아?"에 즉답하는 홈 화면.
- **시장 상태 배너** (상단) — 오늘 시장 리스크온/오프 요약. 클릭 시 탭 5로 이동
- 종목 기본정보 (현재가·등락률·거래량·시가총액)
- 종합 방향성 게이지 (최종 매수/매도 라벨)
- 지표별 기여도 요약 (막대)
- 축소판 캔들 + VWAP 차트
- 신호 히스토리 — 당일 신호 변화 타임라인

### 탭 2 — 기술적 분석 _(차트 딥다이브)_
- 메인 캔들 차트 (이평선·VWAP·볼린저 오버레이)
- 거래량 바
- 서브차트: RSI, MACD, 스토캐스틱
- 지표별 현재값·신호 테이블
- 타임프레임 전환 (1분 / 5분 / 일봉)

### 탭 3 — 수급 _(돈의 흐름)_ ⭐ 국내 단타 핵심
- 외국인·기관 순매수 추이
- 프로그램 매매 동향
- 체결강도 (매수/매도 체결 비율)
- 호가창(Level 2)
- 거래원 정보 (창구별 매수/매도)

### 탭 4 — 리스크 / 전략 _(실전 매매 계획)_ ⭐
- 진입가 입력 → ATR 기반 손절가/목표가 자동 제안
- 손익비(R:R) 계산
- 포지션 사이징 (계좌 크기·리스크 % → 매수 수량)

### 탭 5 — 매크로 / 시장 _(숲을 보는 화면)_ ⭐ 신규
종목과 무관하게 시장 전체 상태를 보는 전용 탭. 장 시작 전 브리핑용.
- **시장 국면 종합 판정** (리스크온/중립/리스크오프) — 탭1 배너와 동일 로직
- 국내 지수 (코스피·코스닥, 등락, 상승/하락 종목 수)
- 해외 증시 (간밤 S&P·나스닥, 야간 선물)
- 환율·금리 (원/달러, 국고채·미국채)
- 시장 전체 외국인·기관 순매수
- 변동성·심리 (VIX, 공포·탐욕 지수)
- 업종 히트맵 (오늘 강한 섹터)

### 탭 6 — 관심종목 / 스크리너 _(종목 발굴)_
- 워치리스트별 실시간 신호 현황
- 조건 스크리너 (예: VWAP 상향돌파 + 거래량 급증 + RSI 다이버전스)
> 다종목 조회로 API 호출이 많아, 데이터 연동은 실전 계좌·최적화 후. UI는 선구현.

### ⚙ 설정 _(탭 아님 — 아이콘/패널)_ ⭐ 투명성의 핵심
- 스코어링 가중치 조절 (수급 중시 vs 모멘텀 중시 등)
- 프리셋 (수급 중시 / 모멘텀 중시 / 균형)
- 시장 국면 반영 on/off (스코어링 결합 옵션)
- 알림 임계값 설정
- 지표 파라미터(RSI 기간 등) 조정

## 10. 개발 우선순위 (로드맵)

| 단계 | 범위 | 비고 |
|------|------|------|
| **코어 (필수)** | 탭 1·2·3 (종합 신호 / 기술 / 수급) | 서비스의 최소 완결 형태 |
| **맥락 (권장)** | 탭 5 (매크로) + 탭1 배너 | 매크로 소스(FDR/yf/FRED) 연동 |
| **차별화 (강력 추천)** | 탭 4 + 설정 패널 | 리스크 도구 + 가중치 커스터마이징 |
| **확장 (v2)** | 탭 6 (스크리너) | 다종목 = API 호출 급증 → 실전 계좌·최적화 후 |

**작업 순서 제안**
1. `core/` 로직 완성 (indicators + macro + scoring) → MockProvider로 검증
2. `KISProvider` + `MacroDataProvider` 실연동
3. FastAPI 엔드포인트 구성
4. Claude Design UI 확정 → 본 문서 UI 섹션 비주얼 채우기
5. React 프론트 구현 (Claude Code)

## 11. 제약사항 / 유의점

- **API 키 필수**: KIS는 한국투자 계좌 + 앱키 발급 필요. 이용기간 1년(갱신), 초당 호출 제한 있음.
- **매크로 소스 이원화**: 국내는 KIS, 해외·환율·VIX는 FDR/yfinance/FRED. 소스별 지연·신선도 다름 → as_of 라벨 필수.
- **공포·탐욕 지수**: 공식 API가 없어 비공식 소스 필요할 수 있음. 대체 지표(예: VIX 단독) 준비.
- **모의투자 계좌 호출 제한**: 단일 조회는 무방하나 연속 호출 많은 기능(스크리너)은 실전 계좌 권장.
- **컨테이너 테스트 불가**: 실 API는 개인 인증·로컬 실행 필요 → 개발은 로컬(Claude Code)에서.
- **신호는 참고용**: 지표는 후행 특성. 최종 진입·청산은 차트·호가·수급을 직접 판단. 손절 규율·손익비 관리가 승률보다 중요.
